# M3–M5 实机测试指南

适用:干净的 Windows 10/11 x64 机器(或虚拟机)。安装包:`src-tauri/target/release/bundle/nsis/Mfork_0.1.0_x64-setup.exe`。

> 测试机上如果也跑着其他代理客户端(Clash/Sparkle 等),先完全退出它们,
> 否则系统代理和 TUN 会互相覆盖,结果不可信。

## 0. 安装与首启

1. 运行安装包 → 启动 Mfork
2. **预期**:主窗口显示,概览页几秒内变为「运行中」(内核自启)
3. 订阅页导入一条真实订阅(或本地 yaml),代理页应出现策略组

## 1. M3 系统集成

| 步骤 | 预期 |
|---|---|
| 设置 → 系统代理 开 | 浏览器(关掉其他代理插件)能走 Mfork 上网;`设置→网络→代理` 显示 127.0.0.1:随机端口 |
| 概览页看流量 | 曲线/速率有数据,连接页出现浏览器进程的连接 |
| 系统代理 关 | 系统代理设置被清除 |
| 关闭主窗口(点 X) | 窗口隐藏,托盘图标还在,内核不退出 |
| 托盘左键 | 窗口恢复 |
| 托盘右键 → 切换 全局/规则/直连 | 概览页模式同步变化;托盘菜单勾选同步 |
| 托盘右键 → 系统代理 | 与设置页开关联动 |
| 再次双击安装的 exe(单实例) | 不开第二个实例,已有窗口被唤起 |
| 设置 → 开机自启 开 → 重启系统 | Mfork 自动启动 |
| 设置 → 静默启动 开 → 退出并重开 | 只出现托盘图标,不弹窗口 |
| 托盘 → 退出 | mfork.exe 与 mihomo.exe 进程都消失;若系统代理开着,退出后系统代理被清除 |

## 2. M5 提权服务

| 步骤 | 预期 |
|---|---|
| 设置 → TUN 模式 → 此时「启用 TUN」开关 | 应为**禁用**状态,提示需先安装服务 |
| 点「安装服务」→ UAC 点**否** | 报「用户取消了 UAC 授权」,无副作用 |
| 点「安装服务」→ UAC 点**是** | 状态变「运行中 · 内核可以 SYSTEM 权限启动」 |
| Win+R `services.msc` | 存在 **Mfork Service**,状态=正在运行,登录身份=本地系统,启动类型=自动 |
| 重启系统(可选) | 服务随系统自启,Mfork 里状态仍为运行中 |

## 3. M5 TUN 模式

1. 关闭系统代理开关(排除干扰),开启「启用 TUN」
2. **预期**:
   - 内核自动重启;`控制面板→网络连接` 出现新适配器(名称含 Mihomo/WireGuard 类虚拟网卡)
   - 任务管理器里 mihomo.exe 的所有者为 SYSTEM(详细信息页加「用户名」列)
   - 浏览器**不设任何代理**也能按规则上网(TUN 全局接管)
   - 连接页能看到各进程的连接(QQ、浏览器等)
3. DNS 劫持验证:`nslookup example.com` → 返回 `198.18.x.x`(fake-ip 段;需同时开启设置页 DNS 接管,或订阅自带 fake-ip)
4. 关闭 TUN → 适配器消失,网络恢复直连
5. TUN 开着时直接 托盘→退出 → mihomo 结束、适配器消失、网络恢复(**重点回归项**:确保不会把测试机网络搞挂)

## 4. 异常路径

| 步骤 | 预期 |
|---|---|
| 任务管理器强杀 mihomo.exe(直连模式) | 概览页变「内核异常:意外退出」;系统代理若开着会被自动清除 |
| TUN 模式下强杀 mihomo.exe | 2 秒内 GUI 报意外退出;重新点启动可恢复 |
| 点「卸载服务」→ UAC 是 | services.msc 里 MforkService 消失;TUN 开关回到禁用态 |

## 5. 收尾

- 设置页卸载服务 → 控制面板卸载 Mfork
- 检查:服务列表无 MforkService、无残留 mihomo 进程、系统代理为关、无残留虚拟网卡

## 已知边界

- 服务固定使用**安装时**的内核路径;将来 Mfork 升级换内核路径后需重装一次服务
- TUN 与其他客户端的 TUN/系统代理互斥,同开必然打架
- 杀毒软件可能对 wintun.dll / 服务安装报警,属 TUN 类工具常见误报
