# M6 實機測試指南

適用:Windows 10/11 x64(macOS/Linux 除 TUN 服務外流程相同)。先完成 `docs/TESTING-M5.md` 的 0 節安裝與首啟。

## 1. 內核升級 / 版本通道 / GeoData

| 步驟 | 預期 |
|---|---|
| 設置 → 內核 → 檢查更新 | 副標顯示「Stable 最新 vX.Y.Z · 大小」;若與當前相同顯示「已是最新版本」 |
| 版本通道切到 Alpha → 檢查更新 | 顯示 `alpha-g<hash>` 版本 |
| 升級到 …(內核運行中) | 按鈕顯示「下載中 N%」→「安裝中…」;完成後內核自動重啟,概覽頁版本變為新版本;副標變「運行中 · 自升級版本」 |
| 已裝提權服務時升級 | 額外彈出一次 UAC(重新指向新內核);拒絕時提示「服務未重新指向新內核」,非 TUN 模式仍可用 |
| 恢復自帶版本 | 確認後內核重啟,版本回到安裝包自帶;`%APPDATA%\app.mfork.desktop\core-bin\` 被刪除 |
| GeoData 更新(內核運行中) | 顯示「GeoData 已更新」;`core\` 目錄下 geoip/geosite 檔案時間戳更新 |
| 斷網 / GitHub 不可達 | 顯示錯誤,不影響內核 |

升級後的內核放在 `%APPDATA%\app.mfork.desktop\core-bin\`,wintun.dll 會一併複製過去。

## 2. 網絡:固定端口 / 局域網 / IPv6

| 步驟 | 預期 |
|---|---|
| 混合端口填 7890 | 內核重啟,`外部控制`旁顯示 7890;`netstat -ano \| findstr 7890` 有監聽 |
| 端口被佔用時填入 | 啟動失敗並提示「端口已被佔用」 |
| 允許局域網 開 | 同網段設備以 `本機IP:7890` 能走代理;`netstat` 顯示 0.0.0.0 |
| 清空端口 | 回到每次隨機 |

## 3. 外觀 / 語言

| 步驟 | 預期 |
|---|---|
| 主題 → 淺色 | 全部頁面即時切換;Monaco 編輯器(覆寫頁)同步變淺色 |
| 主題 → 跟隨系統 → 改系統深淺色 | 應用跟隨變化 |
| 語言 → English / 繁體中文 | 所有頁面文字即時切換;托盤右鍵菜單同步變語言 |
| 重啟應用 | 主題與語言保持 |

## 4. 備份

| 步驟 | 預期 |
|---|---|
| 本地備份 → 導出 | 選擇路徑後生成 zip;內含 `profiles/`、`overrides/`、`app-config.json` |
| 刪掉一個訂閱 → 導入恢復 | 確認後訂閱回來,設置頁提示「已恢復」;內核熱重載 |
| 填 WebDAV 地址/用戶名/密碼 → 測試連接 | 「連接正常」;錯誤密碼顯示「認證失敗」 |
| 立即備份 | 「已上傳 mfork-YYYYMMDD-HHMMSS.zip」;WebDAV 上出現 `Mfork/` 目錄 |
| 查看備份 | 列出雲端 zip(新在前)含大小/時間 |
| 恢復 / 刪除 | 恢復同本地導入;刪除後列表即時移除 |

恢復時本機的 WebDAV 帳號設置會保留(不會被備份內的覆蓋)。

## 5. 概覽頁節點地球

| 步驟 | 預期 |
|---|---|
| 首啟(未測速) | 右側地球(72vh,不出血)顯示大陸剪影,本機位置綠點(按系統時區),當前節點藍色實心脈衝點 + 從本機到節點浮在球面上方的藍色弧線、柔光與白色流光頭;下方一行「當前節點 · … · N 條連接 · M 處可用節點」 |
| 拖拽地球 | 跟手旋轉,鬆手有慣性,約 2.5 秒後自動緩慢轉回本機視角 |
| 模式行 TUN 開關 | 未安裝服務時灰顯並提示「需先安裝系統服務」;服務可達時點擊即切換 TUN 並重啟內核,綠點表示已開 |
| 主題切淺色 | 地球變為淺藍海面 + 近白陸地 |
| 節點設 `dialer-proxy`(如 JP 經 HK 撥出)並選中 | 弧線本機 → HK(空心圓) → JP(實心圓)兩段相連,「當前節點」一行顯示 HK → JP;連接頁裡 HK 上無規則的內層連接不會被算成另一條通路 |
| 經混合端口發起連接 | 「當前節點」一行出現「N 條連接」;走其他節點的連接以綠色弧線另畫一條 |
| 窗口 | Windows 無系統標題欄,頂部 32px 與左側圖標欄可拖動,右上角最小化 / 最大化 / 關閉可用;macOS 為原生紅黃綠燈 + 隱藏標題,圖標欄不被遮擋 |
| 代理頁對策略組測速 | 回到概覽,測速成功且名稱可識別地區的節點在地球上出現灰點,底部顯示「N 處可用節點」 |
| 切換節點 | 8 秒內流光終點跟著換 |
| 模式切到直連 | 流光消失,底部顯示「直連模式 · 不經過節點」 |
| 停止內核 | 地球停止擺動,節點與弧線消失 |
| 主題切淺色 | 地球配色跟隨 |

## 6. 連接頁過濾 / 排序 / 五元組

| 操作 | 預期 |
|---|---|
| 頂部切 TCP / UDP 芯片 | 表格只剩該協議;「全部」恢復 |
| 勾「僅活躍」 | 最近有流量的連接保留,空閒連接隱藏 |
| 出站下拉選某節點 | 只顯示出口為該節點的連接;「全部出站」恢復 |
| 點表頭「↓ 速率」「↑ 速率」「下載」「上傳」「開始」 | 按該列排序,再點反向;箭頭指示當前列 |
| 點某一行 | 展開詳情:五元組(協議 源 IP:端口 → 目標 IP:端口)、入站、主機、規則、完整鏈路、進程、開始時間、連接 ID;再點收起 |
| 目標為域名且未解析 | 目標列顯示「遠端解析」而非空白 |
| 過濾後無結果 | 顯示「沒有符合篩選條件的連接」 |

## 7. 應用自動更新(tauri-updater)

前置:GitHub 倉庫 Secrets 設好 `TAURI_SIGNING_PRIVATE_KEY`(`~/.tauri/mfork.key` 內容),推一個 `v0.1.1` tag 讓 CI 產出帶 `latest.json` 的 Release 並發佈(CI 建的是 draft,需手動 publish)。

| 步驟 | 預期 |
|---|---|
| 設置 → 關於 → 檢查更新(本機 0.1.0) | 「發現新版本 0.1.1」 |
| 下載並安裝 | 進度 → 「安裝完成,正在重啟…」→ 應用重啟為新版本(Windows 為靜默安裝) |
| 無新版本 | 「已是最新版本」 |
| endpoint 不可達 | 顯示「檢查更新失敗」 |

## 8. macOS / Linux 提權服務（待實機驗證）

前置：在該平台 `node scripts/fetch-core.mjs && node scripts/build-service.mjs && pnpm tauri build`，安裝產出的 .dmg / .AppImage / .deb。

| 步驟 | 預期 |
|---|---|
| 設置 → TUN 模式 → 安裝服務 | macOS 彈系統管理員密碼框(osascript),Linux 彈 polkit 授權;完成後狀態變「運行中 · 內核可以 SYSTEM 權限啟動」 |
| 檢查安裝痕跡 | macOS:`/Library/LaunchDaemons/app.mfork.service.plist` 與 `/Library/Application Support/Mfork/{mfork-service,service.token,core-path.txt}`;Linux:`/etc/systemd/system/mfork-service.service` 與 `/usr/local/lib/mfork/` |
| 啟用 TUN | 內核由 root 啟動,`ifconfig` / `ip a` 出現 utun/Mihomo 接口,瀏覽器流量走代理 |
| 內核升級後 | 再彈一次授權重新釘定 core-path.txt 指向 `core-bin/`,TUN 仍可用 |
| 退出 GUI | daemon 仍在,內核已停(`ps` 無 mihomo) |
| 卸載服務 | 授權後 plist/unit 與安裝目錄被移除,狀態回「未安裝」 |
| 故障排查 | macOS 看 `/tmp/mfork-service.log`,Linux 看 `systemctl status mfork-service` |
