# M6 實機測試指南

適用:Windows 10/11 x64(macOS/Linux 除 TUN 服務外流程相同)。先完成 `docs/TESTING-M5.md` 的 0 節安裝與首啟。

## 1. 內核升級 / 版本通道 / GeoData

| 步驟 | 預期 |
|---|---|
| 設置 → 內核 → 檢查更新 | 副標顯示「Stable 最新 vX.Y.Z · 大小」;若與當前相同顯示「已是最新版本」 |
| 版本通道切到 Alpha → 檢查更新 | 顯示 `alpha-g<hash>` 版本 |
| 升級到 …(內核運行中) | 按鈕顯示「下載中 N%」→「安裝中…」;完成後內核自動重啟,概覽頁版本變為新版本;副標變「運行中 · 自升級版本」 |
| 已裝提權服務時升級 | 額外彈出一次 UAC(重新指向新內核);拒絕時提示「服務未重新指向新內核」,非 TUN 模式仍可用 |
| 恢復自帶版本 | 確認後內核重啟,版本回到安裝包自帶;`%APPDATA%\app.mfork.desktop\core-bin\` 被刪除 |
| GeoData 更新(內核運行中) | 顯示「GeoData 已更新」;`core\` 目錄下 geoip/geosite 檔案時間戳更新 |
| 斷網 / GitHub 不可達 | 顯示錯誤,不影響內核 |

升級後的內核放在 `%APPDATA%\app.mfork.desktop\core-bin\`,wintun.dll 會一併複製過去。

## 2. 網絡:固定端口 / 局域網 / IPv6

| 步驟 | 預期 |
|---|---|
| 混合端口填 7890 | 內核重啟,`外部控制`旁顯示 7890;`netstat -ano \| findstr 7890` 有監聽 |
| 端口被佔用時填入 | 啟動失敗並提示「端口已被佔用」 |
| 允許局域網 開 | 同網段設備以 `本機IP:7890` 能走代理;`netstat` 顯示 0.0.0.0 |
| 清空端口 | 回到每次隨機 |

## 3. 外觀 / 語言

| 步驟 | 預期 |
|---|---|
| 主題 → 淺色 | 全部頁面即時切換;Monaco 編輯器(覆寫頁)同步變淺色 |
| 主題 → 跟隨系統 → 改系統深淺色 | 應用跟隨變化 |
| 語言 → English / 繁體中文 | 所有頁面文字即時切換;托盤右鍵菜單同步變語言 |
| 重啟應用 | 主題與語言保持 |

## 4. 備份

| 步驟 | 預期 |
|---|---|
| 本地備份 → 導出 | 選擇路徑後生成 zip;內含 `profiles/`、`overrides/`、`app-config.json` |
| 刪掉一個訂閱 → 導入恢復 | 確認後訂閱回來,設置頁提示「已恢復」;內核熱重載 |
| 填 WebDAV 地址/用戶名/密碼 → 測試連接 | 「連接正常」;錯誤密碼顯示「認證失敗」 |
| 立即備份 | 「已上傳 mfork-YYYYMMDD-HHMMSS.zip」;WebDAV 上出現 `Mfork/` 目錄 |
| 查看備份 | 列出雲端 zip(新在前)含大小/時間 |
| 恢復 / 刪除 | 恢復同本地導入;刪除後列表即時移除 |

恢復時本機的 WebDAV 帳號設置會保留(不會被備份內的覆蓋)。

## 5. 應用自動更新(tauri-updater)

前置:GitHub 倉庫 Secrets 設好 `TAURI_SIGNING_PRIVATE_KEY`(`~/.tauri/mfork.key` 內容),推一個 `v0.1.1` tag 讓 CI 產出帶 `latest.json` 的 Release 並發佈(CI 建的是 draft,需手動 publish)。

| 步驟 | 預期 |
|---|---|
| 設置 → 關於 → 檢查更新(本機 0.1.0) | 「發現新版本 0.1.1」 |
| 下載並安裝 | 進度 → 「安裝完成,正在重啟…」→ 應用重啟為新版本(Windows 為靜默安裝) |
| 無新版本 | 「已是最新版本」 |
| endpoint 不可達 | 顯示「檢查更新失敗」 |
