数据面

  • 应用流量有两个入口：系统代理（HTTP / SOCKS5，由 Rust 写入 OS 设置）或 TUN 虚拟网卡（接管全部 IP 流量，含不认代理的进程与 UDP）
  • 内核按规则匹配后二选一：命中代理策略走加密隧道到节点；命中 DIRECT 则从本机直连目标
  • 混合端口每次启动随机分配（可固定），系统代理随之自动重新指向

控制面

  • 前端通过 Tauri IPC 调用 Rust：订阅、覆写、设置、内核启停
  • 运行时数据（流量、连接、日志、延迟）由前端直连内核 REST / WebSocket，不经 Rust 转发
  • Rust 负责 订阅 → 覆写链 → config.yaml 生成管线、按间隔自动更新、内核自升级与备份（外部请求经内核代理出站）

提权边界

  • GUI 全程不提权；TUN 需要特权时由提权服务（Windows SCM / macOS launchd / Linux systemd）以 SYSTEM / root 代启内核
  • 本地 127.0.0.1:33217 JSON-line 协议，仅管理员可写的 token 文件鉴权
  • 内核路径在安装时钉死，请求只能指定配置与数据目录，不能换可执行文件
