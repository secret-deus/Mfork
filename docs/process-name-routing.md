# 按进程名分流（桌面）

## 使用

1. 打开 **规则 → 进程名分流 → 添加进程规则**。
2. 填写进程的文件名，例如 `chrome.exe`、`steam.exe`，不要填安装路径或通配符。输入框可提示当前连接中已经识别到的进程名。
3. 选择/填写目标策略：代理策略组名称、`DIRECT`（直连）或 `REJECT`（拒绝）。运行中的策略组会提供输入建议；离线编辑可手动填写名称。
4. 保存。内核运行时尝试热加载；内核停止时仅保存，在下次启动时生成配置。
5. 可编辑、停用、重新启用或删除规则。删除需要确认。

例如：

| 进程名 | 策略 |
| --- | --- |
| `chrome.exe` | `节点选择` |
| `steam.exe` | `DIRECT` |
| `example-app.exe` | `REJECT` |

## 生效条件与范围

- 必须使用 **规则模式**；全局/直连模式不会按这些规则分流。
- 保存进程规则时，生成配置会带入当前运行模式，避免被订阅中的 `mode` 覆盖。模式尚未读取完成或保存期间发生变化时会提示重试；不会自动切换到规则模式。
- 只有进入 mihomo 的流量能参与匹配。建议使用 TUN；系统代理只对遵循系统代理的程序生效。本功能不会自动开启 TUN 或改变当前模式。
- 按进程名匹配，不是进程树隔离，也不是 PID 隔离。同名进程的不同实例共用该规则。
- 规则只影响后续连接，已有长连接不会被强制关闭。需要立即切换的应用可重新建立连接。
- 进程识别仍取决于操作系统与 mihomo 的权限/支持；本地进程名应按连接监控或系统实际显示的名称填写。
- 当前入口仅限桌面。Android 的 `find-process-mode` 继续为 `off`；从桌面备份带来的规则会保留但不注入 Android 配置，回到桌面恢复后仍可使用。

## 配置行为

规则保存于 `app-config.json` 的 `process_rules` 数组，不修改订阅源文件。旧设置文件默认空数组，无需手动迁移。

```json
{
  "process_rules": [
    { "process_name": "chrome.exe", "target": "节点选择", "enabled": true }
  ]
}
```

生成配置时按保存顺序插入：

```yaml
rules:
  - PROCESS-NAME,chrome.exe,节点选择
  # 后续仍是已有订阅及覆写产生的规则
```

生成顺序是订阅 → 覆写 → GUI 托管字段与进程规则。因此启用的进程规则优先于已有 DOMAIN、RULE-SET 和 MATCH 规则。

- 只插入启用项；空列表/全部停用不改变原有规则列表。
- 目标必须是最终配置中存在的策略组、显式节点或 DIRECT/REJECT。界面主要提供策略组建议；provider 动态节点没有稳定的配置名，不建议直接手填。
- 策略组改名、换订阅或手填错误会导致生成/应用失败，而不是悄悄走 DIRECT。请修改目标或停用对应规则再重试。无效的启用项也会阻止下次启动，规则页在内核停止时仍可编辑。
- 保存失败显示错误并恢复界面；保存成功但热加载失败会保留已保存规则，显示单独提示和“重试应用”。打开规则页本身不会保存或重载配置。
- 限制为 256 条；名称/目标会去掉两端空白，长度分别最多 260/256 个 Unicode 字符。拒绝逗号、控制字符、空字段；进程名还拒绝路径分隔符与通配符。重复进程名按不区分大小写校验。

## 验证

```sh
pnpm test:process-rules
pnpm test:globe
cargo test --manifest-path src-tauri/Cargo.toml --lib
pnpm tauri build --no-bundle
```

- 前端规则校验：21 项用例。
- Rust lib 测试：36 项（包含旧设置兼容、规则优先级、禁用项、非法目标、输入边界和运行模式保留）。
- 浏览器：基于 `tests/app-browser.html` 的官方 Tauri mock，验证 20 项操作与错误处理，包括离线保存、热加载失败重试、保留全局模式、Android 不显示入口。
- 真实内核：使用仓库自带 mihomo v1.19.30，配置语法检查成功；额外在隔离的回环端口上验证实际 `node.exe → REJECT` 拦截、热加载 `DIRECT` 放行以及不匹配规则继续走 MATCH。测试目标也是本机 HTTP 服务，没有外部流量，没有修改系统代理或 TUN；测试进程退出后关闭端口。

浏览器 fixture 只用于测试，不属于正式构建入口。桌面构建不自动启动软件，不会替用户建立连接。
