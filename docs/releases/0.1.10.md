# 0.1.10 Android VPN startup fix

## Confirmed failure

On the connected Android 13 phone, the VPN service established its interface and the child core inherited its descriptor (`/proc/<pid>/fd/<fd>` resolved to `/dev/tun`). Switching from mixed to gVisor did not repair connectivity.

The 0.1.9 diagnostic build exposed the actual startup failure:

```text
Start TUN listening error: build android rules: read packages list: open /data/system/packages.xml: permission denied
```

The generic upstream Android executable initializes its package manager even when no package filters are configured. A normal Android application cannot read that system file. The controller API remains available after this listener failure, so API readiness alone previously produced a false connected state.

## Changes

- Build mihomo v1.19.30 from clean upstream commit `ac017cdd246ce8bd547653d927e7bf77d7ee73d5`, with `with_gvisor,cmfa`. The upstream `cmfa` build path omits privileged Android package-rule discovery. The application's VpnService continues to own routing and application exclusion.
- `node scripts/fetch-core.mjs --android arm64` now builds this pinned core. Git and Go compatible with upstream's go.mod are required (validated with Go 1.24.1). `MFORK_CORE_SOURCE` can select an existing clean checkout at the pinned commit. Do not replace it with the generic Android release executable.
- Android descriptor mode forces gVisor. Mixed/system's TCP listener can otherwise bind the core-derived address rather than the interface address owned by VpnService. Desktop stack selection is unchanged.
- Verify the active controller TUN configuration before reporting startup success. Listener failure or timeout stops the core and releases the VPN instead of leaving a connected black hole.
- Emit TUN startup diagnostics to Android logcat independently of the controller WebSocket.

## Validation

- Rust: 15 unit tests passed, including descriptor-mode stack and DNS injection assertions; service check passed.
- TypeScript/frontend production build, Android Rust release cross-build, Gradle ARM64 release packaging, and script syntax checks passed.
- APK version 0.1.10 / versionCode 1010; original signing certificate verified; installed as an update on the connected Android 13 phone.
- Device log now reports `Tun adapter listening at: tun0(fd=195) ... ip stack: gVisor`, with inherited `/dev/tun`; the packages.xml startup failure is resolved.
- End-to-end browser access still requires the user's device interaction: this phone denies ADB input injection. A successful TUN listener is not recorded as proof of browser connectivity.
