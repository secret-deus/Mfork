# 0.1.11 Android controller compatibility

The 0.1.10 non-root core successfully forwarded browser traffic after a subscription was enabled. However, importing while connected returned HTTP 405 when applying the saved profile. Inspection of the pinned upstream source confirmed that `hub/route/patch_android.go` enables embedded mode for `android && cmfa`, removing PUT and PATCH `/configs` routes. Mfork runs a standalone executable and requires those authenticated controller routes.

The Android builder now uses a Go source overlay for that initializer, setting embedded mode to false while retaining `with_gvisor,cmfa` and the non-root TUN path. The upstream checkout remains clean and pinned; the overlay is tracked in `scripts/android-core/patch_android.go`. The embedded-mode switch also restores mode changes and configuration reloads. Loopback binding and controller authentication are unchanged.

The subscription list now refreshes after an operation fails so a saved import does not look absent. On phones, the subscription name/status and update controls use separate rows instead of squeezing into a desktop row.

Version: 0.1.11 / Android versionCode 1011.

## Validation

- Go overlay build, TypeScript/production frontend build, Android Rust release build and Gradle ARM64 release packaging passed. Two existing mobile dead-code warnings remain.
- APK signature matches the original Mfork certificate. Both packaged native executables/libraries match the newly built inputs byte for byte.
- Installed the signed release on the connected Android 13 phone, preserving its active subscription.
- UI transitions from rule to global to direct and back to rule succeeded without HTTP 405. The controller port and running time remained continuous.
- Updated the active subscription while connected: the page returned to its idle state, displayed the new update time and no error. The core PID remained 10643 and fd 245 still pointed to `/dev/tun`; no manual reconnect was needed. This exercises the same PUT `/configs?force=true` apply path used by first import.
- After reload the overview remained in rule mode with live connections, and the mobile subscription header/update controls fit without the previous horizontal overflow.
- Google browser success was confirmed by the user on 0.1.10 after importing the subscription. This patch's device checks cover config application and mode switching; browser navigation was not repeated by automation.
