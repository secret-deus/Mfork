# Mfork 0.1.22

- 修复服务模式下热重载被内核拒绝的问题（Ubuntu 上报 `PUT /configs?force=true: HTTP 400 — path is not subpath of home directory or SAFE_PATHS`）：提权服务启动内核时其 `-d` 数据目录与界面生成的配置不在同一位置，内核控制器因此拒绝界面传入的配置路径。
- 界面热重载改为发送配置内容（`payload`）而非路径：mihomo 对 payload 不做路径校验，桌面各平台（含服务模式与直连模式）行为一致。
- 提权服务启动内核时设置 `SAFE_PATHS` 为配置所在目录，使基于路径的重载在 Linux/macOS 上同样可用（纵深防御，兼容旧界面）。
- 更新内核控制器冒烟测试与前端传输测试，覆盖 payload 形式的重载请求。

## 升级说明

Ubuntu 用户安装新版 deb 后即生效；仅升级界面而不重装提权服务时，payload 热重载同样可用（不依赖服务的 `SAFE_PATHS` 变更）。
